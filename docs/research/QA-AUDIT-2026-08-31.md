## 1. gdlint Status

**Status: NOT RUN — `gdlint` is not installed on this machine.**

```
$ which gdlint
gdlint not found
$ gdlint scripts/
zsh:1: command not found: gdlint
$ gdlint scripts/
---EXIT:127---
```

`gdlint` is the GDQuest Godot/GDScript linter (commonly installed via `gdtoolkit` / `pip install gdtoolkit`). It is not present on the host. The CI lint step therefore **cannot be executed locally**. This is a tooling gap, not a project defect. To enable on this host:

```bash
pip3 install --user gdtoolkit
# or
brew install gdtoolkit
```

**Recommendation:** Add `gdtoolkit` to `ops/` setup docs or CI pre-flight so the lint step can run. Until then, the static-type grep analysis in section 4 of this report is the best stand-in.

### Dead-signal emit-site details

- **`SignalBus.binthabat_offered` (GameData.gd:148)** — emitted when the morning alms are offered to the monk. No HUD/UI/achievement listener. Either remove the signal or wire it to a reaction (HUD toast, achievement system).
- **`SignalBus.barter_completed` (GameData.gd:107)** — emitted after a successful market barter. Only `tests/run_tests.gd:185` connects (test-only). Production has no listener, so the player gets no feedback on barter success (only the `show_dialogue` from the NPC). Either remove or wire to HUD inventory flash / market line update.
- **`SignalBus.crop_harvested` (GridManager.gd:95)** — emitted on harvest. No consumer. Same fate: wire to HUD toast or delete.
- **`SignalBus.day_night_cycle_changed` (TimeManager.gd:69)** — emitted every minute from `_process` with the day fraction. **No listener anywhere.** This is a 1-per-minute orphan emit loop — silent perf cost and dead contract. Either delete the emit + signal, or wire it to a DayNightAtmosphere shader (per the art style guide).
- **`SignalBus.festival_triggered` (FestivalManager.gd:11)** — emitted when Loy Krathong triggers. No listener. The manager self-emits a fallback `show_dialogue` if the signal is missing, so removing it is safe; or wire to a festival event layer.
- **`SignalBus.energy_changed`** — declared at SignalBus.gd:24 but **never emitted and never connected**. Pure orphan. Remove the line.

### Asymmetry note

`show_dialogue` is emitted 33 times across production scripts but only consumed by `Main._on_show_dialogue` (1 connection). That single consumer renders into the dialogue_panel tween (Main.gd:63), so the pipeline works — but it is brittle. A bug in `Main`'s tween breaks **all 33** dialogue paths.

## 4. Static Typing Gaps — `scripts/` and `scenes/`

**Headline: 155 functions, 0 missing return annotations, 1 untyped variable declaration across the entire production codebase.**

### 4.1 Function return types

All 155 `func` definitions in production code carry an explicit `-> Type` annotation. Verified by AST-style parse (split on the matching `)` that closes the param list, then check the post-params token). Zero gaps.

### 4.2 Function parameter types

All function parameters across production code carry `: Type` annotations. The earlier grep produced false positives because it required `[A-Z]` for the type, but GDScript builtins like `int`, `float`, `bool`, `void` start lowercase. After correctly allowing both, zero untyped params.

### 4.3 Variable declarations (`var`)

**One** untyped `var` declaration found:

```
scenes/entities/Player.gd:64
  var plot = gm.get_plot(cell) if gm.has_method("get_plot") else null
```

`get_plot` is declared `-> PlotState` at `scenes/core/GridManager.gd:104`. The correct annotation is:

```gdscript
var plot: PlotState = gm.get_plot(cell) if gm.has_method("get_plot") else null
```

**Severity: low** — the runtime type is already correct; the annotation is cosmetic but would let the parser catch downstream type errors.
